一、安装与环境配置

1.1 标准安装方法

Kilosort4 (Python 版) — 推荐方式：

# 创建 conda 环境
conda create --name kilosort python=3.9
conda activate kilosort

# 安装（含 GUI）
python -m pip install kilosort[gui]

# 仅 API（无 GUI）
python -m pip install kilosort

关键注意事项：

  • 推荐 Python 3.9–3.11（Python 3.13 可能存在兼容性问题）
  • 使用 Intel/AMD GPU 必须有 NVIDIA CUDA 支持的 PyTorch
  • Apple Silicon (M1/M2/M3/M4) 目前不完全支持，MPS 后端有已知问题

1.2 PyTorch GPU 安装

# 先卸载 CPU 版本的 PyTorch（如有）
pip uninstall torch torchvision torchaudio

# 安装 CUDA 版本（以 CUDA 12.1 为例）
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu121

1.3 常见安装问题及解决

问题原因解决方法

conda create 失败conda 不再推荐安装 PyTorch使用 pip 安装 PyTorch，而非 conda install
no Qt platform plugin缺少 Qt 系统库sudo apt install libxcb-cursor0 (Linux)；或安装 PyQt5
PyTorch 不识别 CUDACUDA 版本不匹配确保 PyTorch CUDA 版本与驱动兼容；检查 torch.cuda.is_available()

2.3 GUI 使用流程

  1. 选择二进制文件 — 支持 .bin, .dat, .bat, .raw
  2. 选择探针布局 — 预设或自定义（.mat, .prb, .json）
  3. 检查/调整参数 — 主参数面板 + 额外设置窗口
  4. 加载数据 — 点击 LOAD 按钮加载并验证数据
  5. 预览 — 查看原始数据、白化数据、探针布局
  6. 运行排序 — 点击 Run 开始全流程排序
  7. 查看结果 — 漂移图、诊断图、spike 位置图
  8. 在 Phy 中策展 — 运行 phy template-gui params.py
三、数据准备

3.1 支持的格式

  • 二进制文件: .bin, .dat, .bat, .raw
  • 数据类型: int16（默认），uint16, int32, float32 等
  • 数据要求: 形状为 (n_channels, n_samples) 的连续二进制文件（C 序）

3.2 数据转换

KS4 GUI 内置转换器支持：Intan .rhd/.rhs、OpenEphys、SpikeGLX、Neuralynx .ncs

# 通过 API 使用 SpikeInterface 转换
from spikeinterface.extractors import read_openephys
from spikeinterface.preprocessing import bandpass_filter, common_reference

3.3 数据准备常见问题

问题解决方法
Bytes in binary file did not divide evenlyn_chan_bin 设置不正确，确认总通道数
float32 数据 spike 检测失败设置 shift 和 scale 使数据范围在 [-100, +100]
多文件记录（同一 session 分段）将文件名以列表形式传入 filename 参数
.rhd 转换失败确保文件完整且使用最新版 SpikeInterface；或先导出为 .dat
HDF5 .h5 文件先通过 SpikeInterface 转换为 .bin
需要排除同步通道使用 bad_channels 排除 SYNC 通道
数据过大（200+ GB）设置 tmin/tmax 分析部分数据；或使用 batch_downsampling
四、探针配置

4.1 内置探针

Neuropixels 1.0（多种模式）、Neuropixels 2.0（单/多shank）、Neuropixels 1.0 NHP

4.2 自定义探针

三种格式：.json / .mat / .prb

JSON 格式（推荐）：

{
    "chanMap": [0, 1, 2, ..., 383],
    "xc": [0.0, 0.0, ..., 0.0],
    "yc": [0.0, 20.0, ..., 7660.0],
    "kcoords": [1.0, 1.0, ..., 1.0],
    "n_chan": 384
}
  • chanMap: 通道在二进制文件中的行索引（0-indexed）
  • xc, yc: 通道的 x, y 坐标（微米）
  • kcoords: shank 编号（同 shank 用相同值）
  • n_chan: 通道总数

4.3 探针配置常见问题

问题解决方法
chanMap 超出二进制通道范围确保 0-indexed，最大值 < n_chan_bin
新建探针 GUI 功能不可用用 JSON 文件手动创建
SpikeInterface 生成的探针无法加载KS4 格式略有不同，需转换为简单字典
多 shank 探针配置不同 kcoords；可结合 shank_idx 分别排序
通道间距过大（如 300μm）KS4 针对高密度优化；低密度需调整参数
2D 阵列探针（MEA/Utah）必须手动设置 x_centers，考虑增大 dminx

七、常见问题分类及解决方案

7.1 Spike 检测问题

7.1.1 未检测到 spike / "No spikes detected"

最常见的错误之一，原因多样
可能原因解决方案
Th_universal / Th_learned 太高降低阈值至 7-8；低 SNR 数据降至 6
通道间距过大（稀疏探针）减小 dmin 和 dminx 为实际通道间距的 0.5-1 倍
数据比例问题（float32）设置 shift 和 scale 使数据落入 [-100, +100]
白化后数据全为 0 / 空白检查探针 chanMap 是否正确；检查 n_chan_bin
TruncatedSVD 错误 (0 samples)降低 Th_single_ch 到 4-5
通道数太少（4-16 通道）设 nearest_chans < 通道数，降低 dminx
高通滤波过于激进降低 highpass_cutoff 至 150-200 Hz
信号极性反转设置 invert_sign=True

7.1.2 检测到太少 spike / 漏检

可能原因解决方案
阈值过高降低 Th_universal (7-8) 和 Th_learned (6-7)
窄波形（fast-spiking）未被检测减小 min_template_size (如 5)
模板覆盖不足减小 dmin/dminx；增加 template_sizes (如 7)
2D MEA / Utah 阵列增大 dminx 至等于通道间距；确保 x_centers 正确
长时间记录中丢失 cluster增加 nblocks (如 5-10) 助力漂移跟踪

7.1.3 检测到太多噪声 / 伪迹

可能原因解决方案
阈值太低提高 Th_universal 至 10-12；Th_learned 至 9-10
光遗传学/电刺激伪迹设置 artifact_threshold (如 500-1000)
电容式舔舐传感器干扰屏蔽/移除干扰通道
ripple 振荡时的异常检测提高 highpass_cutoff 至 400-500 Hz

7.2 聚类问题

7.2.1 过度合并 (Over-merging)

不同神经元的 spike 被合并到同一 cluster

解决方案
降低 ccg_threshold (如 0.15-0.2)
降低 acg_threshold (如 0.1)
在 Phy 中手动分裂合并的 cluster
确保 cluster_neighbors 足够大（≥10）

7.2.2 过度分裂 (Over-splitting)

同一神经元的 spike 被分成多个 cluster

解决方案
提高 ccg_threshold (如 0.3-0.4)
提高 acg_threshold (如 0.25-0.3)
在 Phy 中手动合并相似的 cluster
如果 KS4 比 KS2 严重，尝试降低 Th_learned

7.2.3 KS4 比 KS2.5 产出更少的 "good" unit

多次被报告的常见问题
解决方案
KS4 标签标准更保守，"good" 质量更高但数量更少
降低 acg_threshold 和 ccg_threshold
确认探针配置相同（KS4 与 KS2 探针格式略有不同）
在 Phy 中重新标记：KS4 的 "mua" 可能包含实际可用的 unit

7.2.4 跨通道分裂/重复检测

解决方案
增大 max_channel_distance 有助于合并
在 Phy 中通过 CCG 检查并手动合并
这是一种保守策略的副作用，通常无害

7.2.5 所有 cluster 被标记为噪声

解决方案
检查数据质量：是否有大量噪声/伪迹
检查白化是否正常（查看 GUI 白化数据视图）
提高 Th_universal 减少噪声进入聚类
降低 acg_threshold 使更多 cluster 通过测试

7.3 漂移校正问题

7.3.1 漂移校正方向错误 / 反而变差

现象解决方案
漂移校正沿错误方向移动检查探针 yc 坐标方向；确保 shank 配置正确
漂移估计过大增大 drift_smoothing (如 [0.5, 1.0, 1.0])
nblocks=1 不准确增加至 3-5
慢速漂移未被跟踪nblocks=0 时模板仍有缓慢更新，但不如开 nblocks>1

7.3.2 禁用漂移校正

设置 nblocks=0 完全跳过。适用于：短记录（<5分钟）、急性记录、漂移校正产生错误时。

7.4 内存与性能问题

7.4.1 GPU 内存不足 (CUDA OOM)

解决方案
减小 batch_size（如 30000 或 20000）
减小 cluster_neighbors（如 5）
减小 max_cluster_subset（如 10000）
设置 clear_cache=True（不推荐）
使用 batch_downsampling > 1
通过 shank_idx 按 shank 分别排序
升级 GPU 显存（推荐 ≥8GB，大通道数 ≥24GB）

7.4.2 系统内存 (RAM) 使用过高

现象解决方案
RAM 随时间逐渐增长至 128GB+可能存在内存泄漏；更新版本；重启 Python
大文件 RAM 持续高位通过 tmin/tmax 分段处理
32GB RAM 不足1000+ 通道×数小时，建议 ≥64GB RAM

7.4.3 排序速度太慢

可能原因解决方案
未使用 GPUtorch.cuda.is_available() 应为 True
CPU 版本 PyTorch重装 CUDA 版 PyTorch
GPU 显存太小 (<8GB)减小 batch_size、cluster_downsampling
max_cluster_subset 太大设为 25000 或更低
GUI 比 API 慢大批量推荐用 API
聚类阶段特别慢减少 cluster_neighbors
同时运行多个 KS 实例串行运行

7.4.4 硬件推荐

通道数GPU 显存系统 RAM存储
< 64 通道≥ 4 GB16 GB快速 NVMe SSD
64–384 通道≥ 8 GB32 GB快速 NVMe SSD
384–1024 通道≥ 16 GB64 GBNVMe SSD + 大容量 HDD

九、最佳实践与建议

9.1 排序建议

  1. 先用默认参数运行，再根据结果调整
  2. 检查白化数据视图：正常白化后应清晰看到 spike 波形
  3. 检查漂移散点图：确认漂移估计是否合理
  4. 始终在 Phy 中策展：KS 的自动标签是初筛，手动确认至关重要
  5. 保存 log 文件：kilosort4.log 包含所有运行细节
  6. 每次参数改动后重新排序，对比效果

9.2 版本建议

  • 始终使用最新稳定版：pip install --upgrade kilosort
  • 如果最新版本有问题可回退：pip install kilosort==4.0.3
  • KS4 适合 Neuropixels 高密度探针、自动化流程
  • KS2.5 适合非标准探针、需要更灵活参数控制
